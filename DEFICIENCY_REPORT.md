# DEFICIENCY_REPORT

This report is ordered by severity first, then by impact area. Line numbers refer to the current repository state inspected on 2026-04-06.

| Severity | Deficiency Type | File and Line | Exact Problem | Fix |
| --- | --- | --- | --- | --- |
| P0 | Parsing crash | `lib/delimitedData.ts:92-98` | `parseDelimitedText()` computes `columnCount` with `Math.max(headerRow.length, ...dataRows.map(...), 0)`. On the requested 500k-row benchmark this expands too many arguments and crashes with `RangeError: Maximum call stack size exceeded`. | Replace spread-based max computation with an iterative scan over the rows. |
| P0 | Build / Type safety | `app/page.tsx:235-240`, `lib/shareState.ts:5-24` | The production build currently fails because `serializeShareState()` still requires `delimiter` and `headerMode`, but the page now shares only query/output state. This blocks `npm run build` and `npx tsc --noEmit`. | Split URL-share state from upload parse state, or make parse-setting keys optional and update tests accordingly. |
| P0 | Availability / Query control | `app/api/query/route.ts:151-225`, `lib/csvToSqlite.ts:129-210` | Query execution is fully synchronous with `better-sqlite3` and has no timeout or cancellation path. A recursive CTE or pathological join can monopolize the Node worker indefinitely. | Execute parsing/query work in a worker thread or another interruptible boundary, enforce a configurable timeout, and terminate the worker on timeout or client abort. |
| P0 | Capacity / Memory safety | `app/api/query/route.ts:21`, `app/api/query/route.ts:155-196` | Only per-file size is checked. There is no max file-count limit and no aggregate request-size guard, so many individually valid files can still exhaust memory once all are buffered into `ArrayBuffer`/`Buffer`. | Add configurable `MAX_FILES_PER_REQUEST` and aggregate byte limits before buffering uploads. |
| P1 | Input validation | `app/api/query/route.ts:64-75` | Upload validation trusts filename extension and MIME type only. A binary payload named `data.csv` with a permissive type can still reach the parser and SQLite layer. | Sniff the first bytes / decoded preview for binary characteristics and reject clearly before parse. |
| P1 | Error handling / Security | `app/api/query/route.ts:208-218`, `lib/csvToSqlite.ts:200-206` | Raw parser and SQLite messages are returned to the client verbatim. Those messages can include SQL internals and user filenames, which violates the requested sanitization standard. | Map internal exceptions to safe user-facing errors, keep details in server logs only, and preserve HTTP status discipline. |
| P1 | Type inference | `lib/typeInference.ts:38-59`, `lib/typeInference.ts:85-90` | Digit-only columns with leading zeros are inferred as `INTEGER`, so values like `007` and `01234` lose their formatting irreversibly. | Add a leading-zero heuristic that forces the entire column to `TEXT` when any digit-only non-zero-padded sample is present. |
| P1 | Encoding handling | `lib/textEncoding.ts:21-32` | Text decoding does not auto-detect BOMs before selecting a decoder. UTF-16 files decode as mojibake unless the user manually changes the encoding selector first. | Detect UTF-8/UTF-16 BOMs and override the selected decoder when the byte stream proves a different encoding. |
| P1 | Header detection correctness | `lib/headerDetection.ts:11-63` | Header auto-detection is a small numeric heuristic over at most two rows of meaningful data. All-text datasets, date-heavy files, and single-row exports are easy to misclassify. | Expand the preview sample, score shape consistency across more rows, and keep explicit per-file overrides as the authoritative fallback. |
| P1 | Large-result semantics | `lib/csvToSqlite.ts:44`, `lib/csvToSqlite.ts:180-199` | The backend caps results at 10,000 rows, not the requested 50,000. It also reports `rowCount` as only the visible row count, which can mislead users about truncation. | Raise the cap to the configured target, include explicit truncation metadata, and surface it clearly in the UI. |
| P1 | Client resilience | `app/page.tsx:255-301` | Preview generation is all-or-nothing. If reading or parsing one file throws, the page drops previews for every uploaded file instead of isolating the bad file. | Build previews per file with independent error states and preserve healthy previews. |
| P1 | Documentation drift | `README.md:46-52` | The documented API contract still describes global `delimiter`/`hasHeaders`, but the current route uses per-file `fileSettings` plus legacy fallback behavior. | Update README examples and request docs to match the real current API. |
| P2 | SQLite tuning | `lib/csvToSqlite.ts:151-153` | SQLite tuning is incomplete relative to the requested production configuration. `journal_mode` is `MEMORY` instead of `OFF`, and `cache_size` is never set. | Apply `journal_mode = OFF`, `synchronous = OFF`, `temp_store = MEMORY`, and `cache_size = -64000` for the in-memory workload. |
| P2 | Query performance | `lib/csvToSqlite.ts:84-123`, `lib/csvToSqlite.ts:167-169` | Tables are created without any adaptive indexing. Frequent analyst queries on large tables with `WHERE`/`JOIN` predicates will degrade to full scans. | Sample or analyze high-cardinality columns after load and create indexes automatically above a row threshold. |
| P2 | Parsing configuration | `lib/delimitedData.ts:47-50` | PapaParse is called with `skipEmptyLines: false`, and `dynamicTyping` is not explicitly pinned to `false`. The current behavior works for delimiter-only rows, but it does not match the requested hardened parser configuration. | Set `skipEmptyLines: true` and `dynamicTyping: false`, then preserve delimiter-only rows through explicit row normalization and tests. |
| P2 | Duplicate parsing work | `lib/delimitedData.ts:84-118`, `lib/headerDetection.ts:15-19` | The code parses the same text multiple times: once for delimiter detection, once for row parsing, and again for header detection previews. | Reuse preview data or centralize parsing analysis so delimiter/header/type inference share a single sampled pass. |
| P2 | Type inference allocations | `lib/typeInference.ts:62-68` | `inferColumnTypes()` allocates a full temporary array for every column. Wide datasets amplify memory churn and GC pressure. | Replace the column-by-column remap with one pass of per-column accumulators. |
| P2 | Insert-path allocations | `lib/csvToSqlite.ts:114-118` | Every inserted row allocates a new coerced value array inside the transaction. That adds avoidable GC pressure on large loads. | Reuse per-row buffers or precompute coercion strategies per column to reduce per-row allocation overhead. |
| P2 | Client preview performance | `app/page.tsx:255-309` | Any change to one file's delimiter/header mode causes every uploaded file to be re-decoded and re-parsed. This scales poorly with many files or large files. | Cache decoded text per file identity and recompute only the affected preview. |
| P2 | UI rendering performance | `components/ResultsTable.tsx:122-155` | The results view renders every returned row directly into the DOM. Even the current 10,000-row cap can create a very large DOM and sluggish interaction. | Add pagination and row virtualization so the DOM only contains the visible slice. |
| P2 | Request limits | `app/api/query/route.ts:21` | The upload ceiling is hardcoded at 50 MB and cannot be tuned per environment, which does not meet the requested hardening spec. | Read upload/file-count/result-cap limits from environment variables with validated defaults. |
| P2 | Transport / cancellation | `app/api/query/route.ts:151-225` | The route does not observe request aborts. If the browser disconnects, the server still finishes decoding, parsing, loading, and querying. | Wire request abort handling into the worker/query execution path and stop work as soon as the request is cancelled. |
| P3 | UX / File download | `app/page.tsx:439-447` | Result downloads are emitted as `text/plain;charset=utf-8` regardless of whether the output is CSV or TSV. | Use delimiter-appropriate MIME types such as `text/csv` or `text/tab-separated-values`. |
| P3 | Local storage robustness | `app/page.tsx:311-319` | Query-history persistence assumes `localStorage.setItem()` always succeeds. Private browsing, quota errors, or storage denial can break an otherwise successful query path. | Wrap storage reads/writes in `try/catch` and degrade gracefully when storage is unavailable. |
| P3 | Share-state design drift | `lib/shareState.ts:5-27` | The share-state model still assumes global parse settings even though parsing is now configured per uploaded file. That mismatch caused the current build failure and guarantees future drift. | Narrow share state to the fields that are actually shareable without the uploaded files, or version the shared-state schema. |
| P3 | Benchmarking gap | `package.json:6-11` | The repo currently has no benchmark scripts or baseline artifacts despite the requested benchmarking workflow. | Add a `benchmarks/` suite plus package scripts to run parsing, query, API, and memory benchmarks. |
| P3 | Coverage enforcement | `vitest.config.ts:26-30` | Coverage is reported for `lib/`, but there are no enforced thresholds, so regressions can silently slip through. | Add 90% coverage thresholds for `lib/` and fail CI when they are missed. |
| P3 | CSV export security | `lib/csvExport.ts:1-45` | CSV export correctly escapes delimiters and quotes, but it does not guard against spreadsheet-formula injection when results are opened in Excel or Sheets. | Prefix dangerous leading formula characters or provide an opt-in "safe for spreadsheets" export mode. |
